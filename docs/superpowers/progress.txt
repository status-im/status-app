=== 2026-07-03 — Design session: sds from nimble resolution (issues 0005/0006 filed) ===

User rejected the sds source improvisations left in statusgo.nims after 0002
(NIM_SDS_SOURCE_DIR env → sibling ../nim-sds → git clone at pin): the build
must compile the nim-sds that NIMBLE resolved, nothing else. Brainstormed and
spiked; design written to
docs/superpowers/specs/2026-07-03-sds-from-nimble-resolution-design.md.

Spike results (all local — localhost git serving; nimble 0.22.3 AND master
0.99.1 built from source):
- ?subdir=<path>@#<rev> installs work (rev must come last); each subdir is
  its own name-keyed store entry → per-target packages coexist (the
  store-collision blocker dissolves via target-in-identity).
- Subdir staging contains ONLY the subdir's files — parent repo sources are
  never visible to hooks; paths=@["../.."] does not change that. A target
  subdir package must source sds via requires (build the resolved copy).
- Bin-less packages: only install hooks fire; before-install runs in
  buildtemp and its outputs ARE installed via installDirs.
- Flag-forwarded cross-install is structurally dead on both nimble versions:
  hooks never see --os/--cpu (params/env/defines probed; source confirms
  compilation flags forward only to custom tasks), and the store dir is
  name-version-checksum with no target dimension. Bin compiles DO get the
  flags. → upstream nimble ask recorded (hook flag forwarding +
  target-aware store).

Decisions:
- Issue 0005 (open, unblocked): every statusgo.nims sds task builds the
  nimble-resolved copy — develop-linked checkout in place, store copy via
  .sds-build/ scratch; sibling/clone/env override deleted; patched sds via
  nimble develop --add (wire vendor/nim-sds develop-link for the worktree).
- Issue 0006 (open, upstream-gated): nim-sds targets/<flavor> subdir
  artifact packages reusing the same engine = one-command cross-target
  provisioning; plus file the upstream nimble issue.

Operational gotchas (now in the spec): run `nimble install <url>` from a
neutral dir (inside a package dir vNext also builds THAT package — it began
building nim_status_client into the spike store); file:// URLs bypass subdir
parsing; nimble clones to ~/.nimble/pkgcache regardless of NIMBLE_DIR.

Next pickup order: 0003 (desktop single-graph) or 0005 (engine) — 0005
partially reshapes what 0003 wires, consider doing 0005 first.

Addendum (same session): 0006 gains "sds build unification" — collapse
nim-sds's per-target tasks into ONE parametric build entry point (flags in
nim config keyed by --os/--cpu/defines; tasks become aliases). Verified
limits keeping a thin driver: nimble has no library-artifact concept (bin
builds programs only); localized static flavors are a multi-command
pipeline (no flag equivalent for post-link symbol localization); hooks
can't see --os/--cpu and repeat same-version installs silently no-op (not
overwrite); env-keyed dispatch (SDS_TARGET) leaks into dependency installs
— rejected. Spec updated (design doc + issue 0006).

AMENDED CRITERION: `env` on a System-mode kit is NOT empty — it still prints
PKG_CONFIG_PATH=<kit's own pkgconfig dir>. Without it pkg-config answers from
its built-in search path (brew's Qt at /opt/homebrew/lib on this machine). What
is empty is the generated machinery: no wrapper, no PATH prepend, no override.
The mk has always behaved this way; the dual interface must not diverge.
